Introduction

Overview & Highlights

Traditional C++ compilers such as Clang and GCC carry millions of lines of historical complexity and require hundreds of megabytes in shared libraries (libLLVM, libclang-cpp). While powerful, this makes compile times a bottleneck during rapid edit-compile-test cycles.

winds is built from the ground up for speed, simplicity, and debuggability:

  • Arena-Based Memory Management: Allocations occur in contiguous 64KB memory blocks with bump-pointers, eliminating thousands of heap allocations and enabling instant O(1) process tear-down.
  • FNV-1a String Interning: Identifiers, method signatures, and symbol names are interned once, transforming string comparisons across compilation into fast pointer equality checks.
  • Unified 3-Address Code IR: Clean intermediate representation designed for constant folding, dead-code elimination, and direct register allocation.
  • Global Usability: Once installed via make install, winds is available in your shell just like clang++ or g++.

Setup

Quick Start & Installation

Building winds requires only standard build tools (GCC or Clang to build the compiler itself, and standard GNU as / ld).

Terminal (Bash) 
# 1. Clone the repository
git clone https://github.com/don2e4/winds.git
cd winds

# 2. Build the optimized compiler binary
make

# 3. Install globally to ~/.local/bin (accessible anywhere in $PATH)
make install

# Optional: Install system-wide to /usr/local/bin
# sudo make install PREFIX=/usr/local

# 4. Verify installation
winds --version

Compiling Your First Program

Create a sample C++ file named hello.cpp:

hello.cpp 
class Greeter {
private:
    int id;
public:
    Greeter(int greeter_id) {
        this->id = greeter_id;
    }

    int computeScore(int base) {
        return this->id * base + 42;
    }
};

int main() {
    Greeter g(3);
    int result = g.computeScore(10);
    return result; // Returns 72 (3 * 10 + 42)
}

Compile and run directly anywhere without specifying relative directory paths:

Terminal 
# Compile directly with winds
winds hello.cpp -o hello

# Execute
./hello
echo $?
# Output: 72

Classes, Structs & Member Functions

winds implements standard C++ classes and structs with explicit member alignment and layout calculation. Methods automatically receive an implicit this pointer as their first argument in accordance with the System V AMD64 ABI.

classes_example.cpp 
class Rectangle {
private:
    int width;
    int height;

public:
    Rectangle(int w, int h) {
        this->width = w;
        this->height = h;
    }

    int getArea() {
        return this->width * this->height;
    }

    bool isSquare() {
        return this->width == this->height;
    }
};

Constructors, Destructors & RAII

Constructors are executed immediately upon declaration of stack or heap variables. When a stack-allocated object reaches the end of its enclosing scope block, the compiler automatically inserts a call to its destructor (~ClassName()).

raii_example.cpp 
int g_cleanup_count = 0;

class ResourceGuard {
public:
    ResourceGuard() {
        // Resource acquisition logic
    }

    ~ResourceGuard() {
        // Automatically invoked on scope exit
        g_cleanup_count = g_cleanup_count + 1;
    }
};

void scopedWork() {
    ResourceGuard guard;
    // ... work performed here ...
    // guard.~ResourceGuard() emitted automatically here
}

Dynamic Memory (new & delete)

Dynamic allocation with new computes the target type's size, invokes the system heap allocator (malloc), and subsequently executes the class constructor on the allocated block. delete invokes the destructor before releasing the memory via free.

memory_example.cpp 
class Node {
public:
    int value;
    Node* next;

    Node(int v) {
        this->value = v;
        this->next = 0;
    }
};

void heapExample() {
    // Allocates sizeof(Node) and runs Node::Node(42)
    Node* item = new Node(42);

    int val = item->value;

    // Destructs and frees memory
    delete item;
}

Namespaces & Scope Resolution (::)

Full support for nested namespaces, explicit scope resolution with ::, and using namespace directives that import symbol sets into the current lexical scope.

namespace_example.cpp 
namespace Graphics {
    namespace TwoD {
        class Point {
        public:
            int x;
            int y;
            Point(int px, int py) {
                this->x = px;
                this->y = py;
            }
        };
    }
}

int main() {
    // Fully qualified declaration and construction
    Graphics::TwoD::Point pt(10, 20);

    using namespace Graphics::TwoD;
    Point pt2(5, 15);
    return pt.x + pt2.y; // 25
}

Function Overloading & Name Mangling

Functions and class methods can share the same name with different parameter arity and types. The semantic analyzer generates unique assembly labels prefixed with _W_ encoding namespace hierarchy and argument signatures.

overload_example.cpp 
// Two distinct overloads
int multiply(int a, int b) {
    return a * b;
}

int multiply(int a, int b, int c) {
    return a * b * c;
}

int main() {
    int x = multiply(3, 4);       // Dispatches to 2-parameter symbol
    int y = multiply(3, 4, 5);    // Dispatches to 3-parameter symbol
    return x + y;                 // 12 + 60 = 72
}

References & Pointers

Supports pass-by-reference (T&) with automatic pointer dereferencing semantics, eliminating explicit address-of and dereference syntax at call sites.

references_example.cpp 
// Classic reference-based swap
void swap(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 100;
    int y = 200;
    swap(x, y);
    // Now x == 200, y == 100
    return x - y; // 100
}

Control Flow & Operators

Supports for loops, while loops, conditionals (if, else), compound blocks, break, continue, and all standard arithmetic, logical, bitwise, and comparison operators.

control_flow.cpp 
int sumEvens(int limit) {
    int total = 0;
    for (int i = 0; i < limit; i = i + 1) {
        if (i % 2 != 0) {
            continue;
        }
        total = total + i;
    }
    return total;
}

Internals

Compiler Architecture

The architecture follows a streamlined, highly decoupled pipeline designed for minimal memory indirection and high instruction-cache locality:

Source (.cpp) UTF-8 Buffer
➔
Lexer FNV-1a Interning
➔
Parser Recursive Descent AST
➔
Semantic Analyzer Type & Scope Resolver
➔
IR Generator 3-Address Code Module
➔
Optimizer Const Fold & DCE
➔
Codegen System V AMD64
➔
Binary (.out) GAS & Linker

Key architectural components located in src/:

  • src/arena.c: Custom chunked bump allocator. Zero fragmentation, instantaneous free.
  • src/str.c: String interning table with 32-bit FNV-1a hashing.
  • src/lexer.c: Fast scanner supporting identifiers, numeric literals, operators, and comments.
  • src/parser.c: Operator-precedence parsing with unlimited token lookahead for complex declarations.
  • src/sema.c: Type hierarchy, class layout computation, method mangling, and overload resolution.
  • src/ir.c & src/opt.c: 3AC intermediate representation generation and peephole passes.
  • src/codegen_x86.c: 16-byte stack frame alignment, System V ABI register mapping, and GAS syntax emission.
Deep Dive

Interactive IR & Assembly Showcase

Compare how a C++ method is lowered from high-level source code, to winds 3-Address Code Intermediate Representation, to final optimized x86_64 assembly: 

class Calculator {
public:
    int factor;

    Calculator(int f) {
        this->factor = f;
    }

    int multiply(int x) {
        return this->factor * x;
    }
};
; Winds Linear 3AC Intermediate Representation
function _W_Calculator_multiply(this: ptr, x: i32) -> i32:
    t0 = load.i32 [this + 0]       ; load this->factor
    t1 = mul.i32 t0, x             ; compute this->factor * x
    ret.i32 t1                     ; return product

function _W_Calculator_ctor(this: ptr, f: i32) -> void:
    store.i32 [this + 0], f        ; this->factor = f
    ret.void
# GNU Assembler (GAS) System V AMD64
    .globl  _W_Calculator_multiply
    .type   _W_Calculator_multiply, @function
_W_Calculator_multiply:
    pushq   %rbp
    movq    %rsp, %rbp
    movq    %rdi, -8(%rbp)        # %rdi = this pointer
    movl    %esi, -12(%rbp)       # %esi = x parameter
    movq    -8(%rbp), %rax
    movl    0(%rax), %eax         # load factor
    imull   -12(%rbp), %eax       # factor * x
    movq    %rbp, %rsp
    popq    %rbp
    ret

Frequently Asked Questions

Common questions regarding architecture, standard conformance, and deployment:

LLVM is a magnificent engineering feat, but it introduces immense build times, huge binary footprints (typically 100MB+ per toolchain), and complex C++ API bindings. By generating high-quality x86_64 assembly directly through a clean 3-address code IR, winds achieves 0.29 ms compile latency and a 325 KB executable size while remaining completely self-contained.
Sub-millisecond speed is the result of three foundational design choices:
1. Block Bump Arena Allocation: Zero heap fragmentation and no fine-grained malloc/free overhead during AST and IR construction.
2. String Interning: Token strings are converted to 64-bit pointers upon scanning, making semantic symbol lookups fast integer comparisons.
3. Single-Pass Direct Lowering: The IR translates directly to System V AMD64 instructions without multi-megabyte intermediate graphs.
Yes! Because winds complies with the standard System V AMD64 calling convention (passing integer and pointer arguments in %rdi, %rsi, %rdx, %rcx, %r8, %r9), you can declare external functions such as malloc, free, printf, and exit and call them seamlessly.
The semantic analyzer maintains a scoped symbol table. When a variable of class type with a destructor is instantiated on the stack, it is registered in the current scope frame. When the parser exits the compound statement or encounters a return statement, calls to all active destructors in that scope are emitted in reverse order of declaration before function epilogue emission.
winds employs a deterministic name mangling scheme. Symbols are prefixed with _W_, followed by their namespace path or class owner, member name, and a typed signature suffix (e.g. _W_Math_add_2_i32_i32). This avoids symbol collisions in object files and ensures full compatibility with the GNU Assembler and Linker.
Currently, winds natively targets Linux x86_64 (AMD64) using GNU Assembler (as) syntax and ELF ABI. Support for macOS (Mach-O) and ARM64 (AArch64) is on the development roadmap.
